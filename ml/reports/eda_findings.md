# EDA findings (day 1)

Aggregate counts over the 4,800 train+validation tickets. No ticket text is quoted here.
These points decide the day-1 features and the post-processing rules.

- Class imbalance is large: `payment_refund` is 864 (18.0%) and `spam_irrelevant` is 144 (3.0%). Headline metric is macro-F1. Accuracy alone will flatter a model that sticks to the head classes.
- Secondary labels are rare (480 / 4800, 10.0%) and only five classes occur: ride_trip_issue 162, payment_refund 156, app_technical 54, delivery_delay 54, order_missing_wrong 54. The secondary head is one-vs-rest over those five, plus a threshold. Do not emit any other class as secondary.
- Urgency is 480 / 4800 (10.0%). It is exactly zero on account_promo 0/432, app_technical 0/384, general_inquiry 0/240, spam_irrelevant 0/144. `safety_conduct` is urgent on 144/192 (75.0%). Force those four categories to non-urgent after the model. Spam also forces `secondary_category` null (schema rule, and the data agrees).
- Language mix matches the brief (en 35.0%, singlish 25.0%, si 20.0%, ta 15.0%, mixed 2.5%, tanglish 2.5%). `language` is not a model feature and is not sent by the API. Char n-grams are the robustness tool for Singlish and Tanglish spelling.
- Channels: chat 2160, email 1440, call_transcript 1200. Non-empty subject counts by channel: call_transcript 0, chat 0, email 1440. Subject shows up on email and not on chat or calls, and the longest subject is far under the 500-character cap. `build_input` always includes the channel and includes the subject only when normalization leaves it non-empty.
- Text is short relative to the 10,000-character API cap: min 36, median 276, p95 629, p99 768, max 985. 3616 / 4800 texts contain embedded newlines (chat and call transcripts). Collapse whitespace in one shared function used by training and serving.
- This release is already NFC (0 texts differ). Still normalize to NFC on the way in, because a later set might not be, and keep ZWJ (U+200D) and ZWNJ (U+200C); Sinhala conjuncts depend on them. Lowercase Latin letters only.
- Injection-style phrasing matches 116 tickets. There is no instruction channel: the model sees that text as tokens. Keep an error-analysis slice for it; do not add a special parser.
- Resolved/historical wording matches 379 tickets, and quoted-correspondence markers match 86. DATA_NOTES say a resolved safety complaint is not urgent and quoted resolved mail is background. That is a slice for error analysis, not a hard keyword rule, until we measure precision.
- The joint category x language key has 66 cells, minimum count 4, and 2 cells under 5. Five-fold `StratifiedKFold` cannot run on that key. Folds are a seeded shuffle plus round-robin inside each cell (`ml/folds.json`, seed 42, 5 folds), ids only.
- Exact normalized-text duplicates: 0 normalized strings occur more than once. Shared 80-character normalized prefixes: 420, of which 102 appear in both train and validation. Near-duplicate wording is common, so a high validation score is not proof of generalization; the number we compare is the 5-fold OOF macro-F1. Do not use `ticket_id` as a feature.
- Secondary pairs that match the labelling rules: `delivery_delay` + `payment_refund` 54, `order_missing_wrong` + `payment_refund` 48. Most common pairs: delivery_delay+payment_refund 54, lost_item+ride_trip_issue 54, account_promo+app_technical 54, payment_refund+delivery_delay 54, food_quality+payment_refund 54, payment_refund+order_missing_wrong 54, payment_refund+ride_trip_issue 54, safety_conduct+ride_trip_issue 54. A refund asked because food is late is secondary to delay; a refund because food is missing is secondary to the missing order. The primary head will not learn that on its own.
- Emoji appears in 418 tickets. Emoji-only text is still a valid API input and must return 200. Word n-grams can drop it; char n-grams should keep the vector from being empty.
- Majority-class floor (always `payment_refund`, secondary null, urgent false), scored on the 800 validation tickets: accuracy 0.180, macro-F1 0.028, secondary exact 0.900, urgent F1 0.000, ECE 0.820. Anything we ship has to beat this macro-F1 with the same metric code. The ECE is bad on purpose: confidence is 1.0 on every row.
- Serving rules for v0, taken from the points above: TF-IDF word and char n-grams on `build_input(channel, subject, text)`; no `language` and no `ticket_id`; secondary over the five observed classes; force non-urgent on account_promo, app_technical, general_inquiry, and spam_irrelevant; spam clears secondary; team comes only from the fixed table.
